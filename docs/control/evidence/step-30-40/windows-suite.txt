The last failure, at ce707119, was
`test_verify_flags_a_member_that_reached_the_archive_unredacted`:

  AssertionError: assert 'user_dir' in ('home_dir', 'windows_user_profile',
                                        'absolute_path', 'literal:account_name')

Not a test artefact. The redactor enumerated whole spellings of a literal path
— all-`/`, all-`\`, all-doubled, all-percent-encoded — so a path that *mixed*
them (`C:\Users\Иван/Zomboid`, which is what `f"{path}/name"` produces) matched
none of them and fell through to the shorter `home_dir` literal. The path was
still struck out, so this was not a leak; it came out under `<USER_HOME>`
instead of `<ZOMBOID>` and was reported under the wrong label, which means the
same file produced a different line on Windows than on Linux. That is the one
guarantee a placeholder exists to provide.

Fixed at 2c4fd3c8 by matching each separator position independently rather than
enumerating mixtures, which are exponential in the number of separators.
Regression tests: tests/contract/test_windows_path_shapes.py, six of which fail
against the previous redactor.
